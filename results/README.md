# Cross-backend comparison: CPU vs GPU (CUDA) vs Cerebras CS-3

All three backends run the identical pipeline (all-pairs global alignment ->
UPGMA guide tree -> progressive profile-profile merge) on the identical
input: `test/plasmid_sample.fasta` (10 real NCBI plasmid sequences, one per
species -- E. coli, K. pneumoniae, S. enterica, S. aureus, E. faecium,
A. baumannii, B. cereus, P. aeruginosa, C. perfringens, N. gonorrhoeae -- all
exactly 1000bp), with the same default `ScoreParams` (match=2, mismatch=-1,
gap=2). guide_tree.cpp and progressive.cpp are the *same unchanged source*
across all three backends -- only the all-pairs scoring stage differs by
hardware. So `score_matrix.txt` is the number to diff first; if that matches
exactly, `guide_tree.newick` and `final_msa.fasta` are guaranteed to match
too (same deterministic code fed the same numbers).

Each backend's directory should end up with:
- `score_matrix.txt` -- n x n whitespace-separated ints (0 diagonal)
- `guide_tree.newick` -- UPGMA tree, Newick format
- `final_msa.fasta` -- aligned FASTA, one record per input sequence, original IDs
- `full_output.txt` -- full console output (score matrix + tree + MSA + timing)

## cpu/ -- done

Generated by `cs3/milestone2_allpairs/cli/cs3_msa_cli --fasta test/plasmid_sample.fasta --cpu-reference --out final_msa.fasta`,
which calls `align_cpu()` directly (`src/cpu_reference.cpp`, no GPU/CS-3
involved) for every pair, then the same `guide_tree.cpp` / `progressive.cpp`
used by the other two backends.

## gpu/ -- to be run on ACES (CUDA path)

The existing CUDA pipeline (`src/gpu_align.cu`, PT kernel) now supports the
same `--out` flag for direct comparison. On ACES, with this branch pulled
and `test/plasmid_sample.fasta` present (already committed to the repo):

```
module load CUDA/12.6.0
make
./bin/msa_align --fasta test/plasmid_sample.fasta --msa --out results/gpu/final_msa.fasta \
  | tee results/gpu/full_output.txt
```

Then pull just the score matrix and tree out of `full_output.txt` into their
own files the same way `results/cpu/` was built, e.g.:
```
sed -n '/^score matrix:/,/^$/p' results/gpu/full_output.txt | tail -n +3 \
  | awk '{$1=""; sub(/^ +/,""); print}' > results/gpu/score_matrix.txt
grep -A1 '^guide tree' results/gpu/full_output.txt | tail -1 > results/gpu/guide_tree.newick
```
